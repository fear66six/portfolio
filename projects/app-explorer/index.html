项目 01 · 2026.03 — 2026.06

Android 内容安全审查

Agent / 后端开发 · 仓库 fear66six/app_explorer

要解决的问题

面向 Android 应用里的赌博、色情等不良内容审查。系统基于 OpenAI Agents SDK、大模型和 ADB，完成 APK 安装、页面遍历、功能识别、应用分类、过程记录和结果归档。

我负责什么

我设计分层 Agent 工作流，并处理两件具体的事：Qwen/Dashscope 同时启用 Tool Calling 和 JSON Schema 时工具调用失效；直接把完整 UI XML 交给模型会让上下文膨胀，执行也不稳定。

关键做法

  • 工作流分成 Coordinator、Explore、Entry Analysis 和 Classify。Function Calling 把 APK 安装、界面采集、探索、分类和报告串起来，任务状态放在共享上下文里传递。
  • Qwen/Dashscope 同时开 Tool Calling 和 JSON Schema 时，工具调用会失效。适配层在 LiteLLM 上先拿掉结构化约束完成函数调用，拿到工具结果后再恢复 Schema 校验。OpenAI 和 Qwen 因此走同一套返回格式。
  • 导航识别按控件坐标分组，综合位置、控件类型、Resource ID 和标签完整度给候选打分。XML 裁成可点击元素、页面文本和统计摘要，历史工具输出也会压缩，减少无效上下文。
  • 页面是否加载完，用 XML 里的 loading/skeleton，加上截图的灰度、黑屏比例和区域方差一起判断。没加载完就渐进等待并有限重试。模型结果再用 Pydantic、枚举、置信度阈值和错误分类卡住。每轮调用日志、失败截图和 UI XML 都留下，方便回溯。

结果

一条流程可以完成 APK 安装、页面遍历、功能识别、应用分类、过程记录和结果归档。逐轮调用日志、失败截图和 UI XML 都保留，用来定位问题和回溯任务。
